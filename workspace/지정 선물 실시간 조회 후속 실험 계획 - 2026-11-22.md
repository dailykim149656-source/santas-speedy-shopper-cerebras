## 12회 실험이 바꾼 판단

D5027의 첫 호출을 빠르게 하려던 시험에서 12회를 전송했고, 9회가 상품 및 호출 방식 검증을 통과했다. 유효 최고는 D5049의 공식 평균 1,060.17 TPS였다. 기존 최고 D5027의 1,354.66 TPS에는 미치지 못했다. 세 건의 제공사 429는 실패로 집계했다. [12회 결과와 영상](<D5027 첫 호출 TPS 실험 결과 - 2026-11-22.md>)

대조군 A의 유효 실행은 3/4였다. B에서 평균 이득이 관측됐지만 유효 쌍이 두 개였다. C는 네 번 모두 올바른 상품을 찾았으나 첫 호출은 세 쌍 중 한 번만 이겼다. 조건별 성공률에는 제공사 혼잡도 영향을 줬으므로 C의 높은 성공률을 지침의 효과로 단정하기 어렵다.

후속 실험의 주지표는 **새 세션의 공식 평균 TPS**로 잡는다. 첫 호출 속도와 생성 시간은 원인 분석에 사용한다. 먼저 같은 상품과 카드 형식으로 조회 시작 위치를 비교하고, 두 호출 방식의 추가 후보로 최종 도구 정의 제거를 시험한다.

## 가설과 운영진 답변

운영진은 프롬프트에 선물을 지정하고 정해진 쇼핑몰을 플러그인이 실시간 검색해 Kimi가 결과를 출력하는 방식을 허용했다. 순위 지표는 새 세션에서 공식 패치가 표시하는 평균이다. 첫 모델 생성 전에 플러그인이 조회하는 구체적인 실행 순서와 사후 재측정 방식은 답변에서 확정되지 않았다. 선조회 조건의 결과를 공유할 때 실제 순서를 명시한다. [운영진 답변 기록](<쇼핑 바운티 공고 및 운영진 답변 - 2026-11-22.md#L13>)

선물 목록을 사전에 정하는 것을 허용한 답변을 반영해, 지정 상품 5개의 ID나 SKU를 실행 설정에 둔다. 각 실행의 상품명·가격·재고·상세 링크는 요청이 들어온 뒤 판매처에서 조회한다. 하드코딩 설명은 측정 도구 조작 방지에 관한 답변이며, 재검증의 프롬프트·반복 횟수·허용 오차는 미정이다.

한 세션에서 실제 생성이 한 번이면 해당 호출 속도가 공식 평균이 된다. D5009의 최종 호출은 1,792.65 TPS였고 같은 세션의 평균은 1,301.28 TPS였다. 당시 최종 호출에는 이전 도구 결과와 대화 이력이 있었으므로, 새 세션 첫 생성에서 같은 속도가 나오는지가 이번 가설이다. [D5009 원본](<../experiments/test/runs/a9530b69-3aed-4ea9-8fd9-9ee1fcb36b51/evidence.json>)

경쟁팀의 공개 `1402` 스냅샷에는 작은 전용 조회 도구, 짧은 시스템 입력, 일정한 상품 객체의 복사 출력, 최종 호출의 도구 정의 제거가 구현돼 있다. 문서의 평균 1,402·1,425와 사용자가 알려준 1,464를 독립 재계산할 원본 자료는 확인되지 않았다. 공개 구현은 실험 후보를 정하는 근거로 사용한다. 해당 코드의 `description`은 상품명 반복이고 `reason`은 고정 문구이므로, 우리 카드는 실제 가격·통화·재고·구매 옵션 등 조회한 정보를 담는다. | 항목 | 도구 호출 조건 | 선조회 조건 |

## 실행과 증빙

1. **로컬 예행연습, 모델 전송 0회.** 고정 OpenClaw 버전에서 하나의 공개 상품 조회 함수를 도구와 선조회 훅이 공유하게 한다. 훅은 해당 요청과 세션에 연결되고 그 턴에 조회 도구가 허용될 때만 동작한다. 모의 판매처로 정상 5개, 누락·품절, 타 세션, 중복 실행을 확인한다. 현재 검증기는 OpenClaw의 도구 결과를 읽으므로 선조회는 판매처 응답 시각·해시·상품 ID와 현재 세션을 연결하는 별도 검증을 추가한다. 공식 패치는 원본을 유지한다. 고정 버전의 선조회 훅 (로컬 기록) · [기존 도구 검증](<../experiments/test/tools/validate.py#L296>)
2. **구조 비교 8회.** 도구 호출을 A, 선조회를 B로 정의하고 **AB / BA / BA / AB** 네 쌍을 전송한다. 이 문서의 A·B는 새 조건이다. 같은 쌍에서 프롬프트와 선물 목록을 고정한다. 각 쌍에서 두 전송 사이가 15분 이내이고 동일한 상품 5개가 검증되어야 TPS의 짝별 차이에 포함한다. 실패한 전송도 전송 수와 성공률의 분모에 포함한다. B에서 추가 모델 생성이 생기면 실제 평균에 모두 포함하고 단일 생성 가설 충족 여부를 따로 표시한다.
3. **선별과 분기.** B의 탐색용 선별 기준을 유효한 쌍 3개 이상, 공식 평균 3승 이상, 짝별 평균 차이 중앙값 +100 TPS 이상, 상품 검증 성공 횟수가 A 이상으로 제안한다. B가 통과하면 5번의 재확인으로 간다. 기준이 충족되지 않으면 A와 B의 유효 수·중앙값·실패 사유를 보고하고 4번의 두 호출 개선 후보를 검토한다. 유효 쌍 부족은 효과 미확정으로 표시한다.
4. **조건부 도구 제거 비교 4회.** 두 호출 A에서 카드와 나머지 설정을 고정하고, 최종 생성에 전용 도구 정의를 유지하는 K와 제거하는 D를 **KD / DK**로 비교한다. 제거 조건은 최종 생성의 `tools`, `tool_choice`, `parallel_tool_calls` 전송 여부를 바꾼다. 첫 호출의 도구는 두 조건에서 동일하게 제공한다. B 비교에서 429 대기로 유효 쌍이 부족했다면 제공사 회복 후 이 별도 비교를 진행한다. 두 쌍 모두 유효하고 D의 평균이 두 번 모두 개선되면 재확인 후보로 삼는다. 두 쌍은 후보 선별 표본이다. 실제 요청 구성과 서버 응답에서 모든 생성이 기록되는지 확인한다. [경쟁팀의 변경](https://github.com/xinjiav2/agyoneshot/commit/02556b4dcca2d2dbd28b711636e0ca4210e8fc80)
5. **후보 재확인 최대 4회.** 선조회가 선별되면 A–B / B–A, 도구 제거가 선별되면 K–D / D–K를 실행한다. 첫 쌍은 탐색과 같은 입력을 새 세션에서 반복하고, 둘째 쌍은 지정 선물 목록을 바꿔 일반화를 확인한다. 같은 쌍 안에서는 동일한 입력을 사용한다. 두 쌍 모두 상품 검증을 통과하고 후보의 평균이 높으면 재확인 통과로 기록한다. 원래 입력의 재현 결과와 다른 선물의 일반화 결과를 각각 남긴다.

실제 전송 상한은 구조 비교 8회, 조건부 도구 제거 4회, 최종 후보 재확인 4회로 **최대 16회**를 제안한다. 선조회가 바로 선별되면 최대 12회다. 도구 제거까지 후보가 없으면 12회에서 종료한다. 실패도 해당 슬롯을 소비하며 총전송에 포함한다.

모델 요청은 한 번에 하나만 전송하고 main·test·exp 실행 잠금과 실제 구간을 대조한다. 기존 쿨다운과 연속 두 번의 최종 429 시 10분 대기를 적용한다. 대기로 한 쌍의 전송 간격이 15분을 넘으면 해당 쌍의 성능 비교를 제외하고 전송·실패 기록은 보존한다.

매회 공식 평균, 첫·최종 호출별 출력 토큰·서버 시간, 첫 생성 전후 조회 시각, 실제 생성 수, 전체 응답 시간, 상품 검증 성공 여부를 남긴다. 녹화 브라우저를 사전에 준비하고 실행과 병행해 캡처하며 실제 첫 프레임 시각을 기록한다. 상품 상세 페이지 5개는 같은 실행의 판매처 응답과 독립 대조한다.

- **재현성**은 세션 최고, 조건별 유효 평균의 중앙값, 전체 전송 대비 성공률, 다른 문장·선물 목록의 결과를 함께 제시한다. 이 선별 기준은 후속 실험을 위한 제안이며 운영진의 사후 재채점 기준은 미정이다.
