# 공개 저장소에서 찾은 D5027 개선안

**먼저 시험할 변경은 다섯 검색을 그대로 두고, Kimi가 첫 응답에 쓰는 긴 URL을 짧은 검색어로 바꾸는 것이다.** 별도로, 우리 상품 검증기가 실제 상품 페이지 두 곳에서 실패하는 문제는 모델 실험 없이 재현했다. 아래 속도 후보는 아직 측정하지 않았다.

근거는 제출과 연결된 공개 저장소 두 개다. DeLunar는 호출별 토큰 수와 서버 생성 시간이 있어 직접 평균을 계산했다. nishia 팀은 소스·커밋 이력·Discord 영상으로 구조와 표시 점수를 확인했다. 해당 실행의 호출별 시간은 공개 자료에서 확인되지 않아 단계별 수치 비교에는 쓰지 않았다. DeLunar 작성자도 자기 프롬프트로 돌린 대부분의 세션이 평균 950~1,150이었다고 설명했다. 우리 카탈로그는 17회 중 1회 성공, 16회는 제공사 429였다. 첫 호출이 172ms 만에 끝났어도 생성한 토큰이 106개여서 618 TPS였다. ### 1. 첫 호출에서 카테고리별 검색어만 전달

D5027은 `filter`, `mixer`, `oscillator`, `echo`, `cable` 다섯 품목에 대해 Kimi가 WooCommerce URL 전체를 각각 `web_fetch`에 전달한다. 다섯 인수 객체를 공백 없이 직렬화하면 총 **725자**다. 같은 검색을 `{"query":"filter"}`처럼 호출하면 합계 **90자**다. 이 635자는 인수 텍스트 차이이며, 모델 출력 토큰이나 TPS 개선량으로 환산할 수 없다. DeLunar에서는 짧은 검색어와 품목당 결과 1개를 지정하고, 도구가 라이브 카탈로그 HTTP 요청을 조립한다. [우리 제출 프롬프트](https://github.com/dailykim149656-source/santas-speedy-shopper-cerebras/blob/4d19e2aad036b49cc09c8cbb508bb870fccb0c8a/runs/cd75e5e0-be7c-471f-a9ab-c9e6f0d1bd77/plan.json#L12-L14) · [DeLunar 프롬프트](https://github.com/Ahmad-FP/cerebras-openclaw-search/blob/7ddb3f5e17af23d31c0f646695ff8ece8dd13a67/prompt.txt#L1-L8) · [검색 구현](https://github.com/Ahmad-FP/cerebras-openclaw-search/blob/7ddb3f5e17af23d31c0f646695ff8ece8dd13a67/gift-search-mcp.mjs#L44-L81)

**우리 적용안.** 기본 Plugin API에 카테고리 검색 도구를 추가하는 실험이다. URL 조립에는 기존 판매처·재고 필터·`per_page=1`·실행별 식별자를 재사용한다. Kimi가 도구 다섯 개를 요청한 뒤 현재 판매 중인 상품을 가져오고, 최종 답변은 기존 번호 매긴 링크 다섯 줄을 유지한다. A는 D5027, B는 검색어 도구로 둔다. 두 방식의 도구 이름·정의도 달라지므로 이 비교에서 확인할 수 있는 효과는 **첫 호출에서 쓰는 도구 인터페이스 전체**다. 반환 본문의 상품 필드·순서·포장을 맞추고, 실제 요청 URL·도구 호출 ID·응답 상품을 보관하면 판매처나 상품 선정 변경과 구분할 수 있다. [기존 URL 조립](<../experiments/test/tools/variants.py#L12>) · [기존 5건 병렬 프롬프트](<../experiments/test/tools/variants.py#L146>)

### 2. 최종 답변과 같은 형식으로 검색 결과를 반환

DeLunar는 이름·URL·가격·판매처를 담은 상품 객체를 만들고 Kimi에 그대로 복사하도록 한다. 우리는 한 번 검색하는 실험에서 도구가 상품명과 URL을 번갈아 14줄·855자로 반환했고, Kimi가 이를 Markdown 링크 5줄·876자로 다시 썼다. 도구가 처음부터 검증된 상품명과 URL을 최종 Markdown 링크 5줄로 렌더링하는 변경을 별도로 시험할 수 있다. 검색어·상품 선정·프롬프트·첫 호출에 노출되는 도구 정의는 같게 두고, 최종 호출의 추론·출력 토큰·서버 생성 시간·TPS를 비교한다. 링크 제목에 대괄호가 포함되는 상품도 검증한다. [현재 도구 반환 형식](<../experiments/test/tools/catalog-search-plugin/index.cjs#L95>) · [실제 대화 기록](<../experiments/test/catalog-benchmark/series-01/catalog-05.json>) · [DeLunar의 출력 지시](https://github.com/Ahmad-FP/cerebras-openclaw-search/blob/7ddb3f5e17af23d31c0f646695ff8ece8dd13a67/prompt.txt#L7-L8)

### 3. 검증 가능한 상품과 유효 세션을 놓치지 않도록 수정

- **실제 페이지를 오판하는 파서.** DeLunar의 Smartoon Kids와 Comfrt 판매 페이지는 모두 HTTP 200이고 `og:type=product`였다. 같은 응답 바이트를 우리 `Page`로 읽으면 두 곳 모두 `AttributeError`가 났다. 값 없는 `class` 속성을 단순 HTML로 넣어도 같은 예외가 난다. HTML 파서가 값 없는 속성을 `None`으로 돌려주는데 현재 구현은 바로 `.split()`을 호출한다. 문자열로 사용하는 속성의 빈 값을 정규화하고, 빈 속성 뒤에 상품 메타데이터가 있는 사례로 검증할 수 있다. 이 변경은 정상 상품을 확인할 수 있는 비율을 개선한다. [파서](<../experiments/test/tools/validate.py#L129>) · [파서를 호출하는 검증기](<../experiments/test/tools/catalog_trial_score.py#L52>) · [원본 상품 목록](https://github.com/Ahmad-FP/cerebras-openclaw-search/blob/7ddb3f5e17af23d31c0f646695ff8ece8dd13a67/README.md#L49-L53)
- **표시 이름과 링크를 쌍으로 대조.** 카탈로그 검증기는 최종 링크 5개의 URL 집합을 도구 반환값과 비교한다. 상품명 A에 상품 B의 링크를 붙이고 B에 A의 링크를 붙이면 URL 집합은 같다. 최종 답변의 `(표시 이름, 목적지 URL)`을 같은 실행의 상품 카드와 짝지어 대조하면 이런 오류를 잡을 수 있다. 호출 수 검사는 실험 방식별로 유지한다. 기존 단일 검색 검증기는 명시적으로 도구 호출 1개만 인정하므로, 5병렬 실험에는 카테고리 5개와 호출 ID 5개에 각각 대응하는 증빙을 검사하는 경로가 필요하다. [최종 링크 검사](<../experiments/test/tools/catalog_trial_score.py#L207>) · [도구 호출 수 검사](<../experiments/test/tools/catalog_trial_score.py#L155>)

## 우선순위와 결과 판정

nishia의 코드에는 첫 호출의 도구 사용 강제, 둘째 호출의 도구 정의 제거, 설치된 OpenClaw 전송 코드 직접 수정이 함께 들어 있다. 우리 실험에서는 도구 정의만 제거한 조건의 유효 중앙값이 **903.72 TPS**(3/6회), 대조군은 **1,072.57 TPS**(2/6회)였다. 첫 호출만 강제한 별도 비교에서는 실험군 두 번 모두 429로 끝났다. 표본이 적고 경쟁작에서도 각 변경의 효과를 분리할 수 없어, 전송 코드 변경은 우선순위를 낮췄다. [nishia 전송 코드](https://github.com/xinjiav2/agyoneshot/blob/4f65cb6e328b062f19a36348d527c98342d60a87/openclaw-patches/apply-patches.mjs#L127-L163) · [우리 18회 비교](<../experiments/test/SPEED1500-RESULTS.md#L9>) · [도구 강제 비교](<D5027-1500-실행기록.md#L85>)

실험을 재개할 때는 **검증기 수정 → 첫 호출 비교 → 최종 출력 형식 비교** 순서가 적절하다. 각 비교를 같은 시간대에 새 세션으로 A–B, B–A 순으로 교대하고, 온도·추론·재시도 정책을 맞춘다. 양쪽 모두 성공한 쌍에서 첫·최종·세션 TPS 차이의 중앙값을 계산하고, 모든 전송을 분모로 429와 상품 5개 검증 통과율을 함께 남긴다. 최고값은 별도로 기록한다. 유효 쌍이 충분히 쌓이지 않으면 개선 여부를 미정으로 둔다.

**1,673 목표의 크기.** 우리 최고 세션의 최종 1,673.94와 DeLunar의 첫 1,482.91을 한 세션에서 낸다고 가정해도 평균은 **1,578.42**다. 우리 최종 호출이 같은 속도를 유지한다면 실제 평균 1,673을 넘기려면 첫 호출은 **1,672.06 초과**가 필요하다. 첫 호출을 개선하는 실험은 근거가 있지만, 그 변경만으로 목표를 넘을지는 측정해야 한다. [공식 패치의 평균 계산](https://github.com/wkasekende/openclaw-speed-patch/blob/e40e9f7b7ec41ad3fa68181ad297db119e755171/openclaw-cerebras-kimi-on-8b18b55.patch#L385-L455)
