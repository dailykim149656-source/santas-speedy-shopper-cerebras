# BrightyBrainiac의 Santa’s Speedy Shopper 출품작

2026년 11월 23일 01:23 KST 기준, 내장 브라우저에서 Cerebras Discord의 작성자 필터로 BrightyBrainiac(`quirkyquests`)을 검색했다. 열람 가능한 서버 검색 결과는 23건이었다. 출품 원글 4건, 데모 교체 댓글 7건, 같은 교체를 반영한 제목 변경 알림 7건, 일반 대화 2건, 바운티 공지의 규정 질문 3건이다. 첨부 MP4 총 11개의 재생 길이를 확인하고, 네 원글의 최신 영상 화면과 설정 ZIP을 대조했다.

**본 출품작은 기본 웹 검색을 사용한 1,365 TPS이고, 최고 기록은 상품 검색을 모델 호출 전에 끝내는 실험형의 1,501 TPS다.** 1,501 실행에서 Kimi가 맡은 일은 실시간 검색 결과를 한 번 출력하는 것이었다. Kimi가 직접 검색을 지시한 제출 중 최고는 1,442 TPS다. 네 최신 영상은 모두 공지의 60초 상한을 넘는다. 심사 결과나 예전 영상의 대체 인정 여부는 확인되지 않았다. [바운티 공지](https://discord.com/channels/1085960591052644463/1573839018964029450/1573839018964029450)

첫 호출과 최종 세션의 배지는 영상에서 확인했다. 두 호출인 세션에서 둘째 호출의 값은 첫 배지와 최종 p90을 대조한 반올림값이다. 시도 횟수와 중앙값은 작성자가 각 기록을 올릴 당시 공개한 값이다. 첨부 ZIP은 프롬프트와 설정을 담고 있으며 전체 시도의 공급자 로그는 제공하지 않는다. 공식 패치의 세션 평균은 서버가 시간을 제공한 모델 호출별 생성 속도의 산술평균이다. 검색·대기 시간은 제외한다. [공식 패치](https://github.com/wkasekende/openclaw-speed-patch/blob/e40e9f7b7ec41ad3fa68181ad297db119e755171/openclaw-cerebras-kimi-on-8b18b55.patch#L385-L449)

### 1. 본 출품 · 검색할 상품과 출력 틀을 프롬프트에 지정

다섯 선물과 브랜드, 긴 검색어 다섯 개, 최종 목록 양식을 프롬프트에 적었다. Kimi가 첫 모델 호출에서 기본 제공 `web_search`를 5개 병렬 요청하고, 둘째 호출에서 검색 결과의 링크를 채운다. 도메인과 상품 URL은 프롬프트에 들어 있지 않다. 설정은 검색어당 결과 1개, `parallel-free`, 추론 `low`, 온도 0.2, 최대 1,600토큰이다. 최종 상품은 Kikkerland 드리퍼, Victoria 주물팬, Iron & Resin 머그, Ox & Pine 저널, Minga 키링이다. [원글](https://discord.com/channels/1085960591052644463/1574062058117529641/1574062058117529641)

영상에는 첫 호출 678토큰·1,327 TPS, 완료 후 844토큰·6초가 보인다. 최종 화면에 응답 아래 **1,339 mean**과 입력창 옆 **1,365 mean**이 동시에 뜬다. 작성자는 응답 배지가 첫 호출을 검색 카드마다 다섯 번 반영한다고 설명했다. 실제로 `(1,327 × 5 + 1,403) ÷ 6 ≈ 1,340`으로 이 설명과 가깝고, 두 호출만 평균하면 정확히 1,365다. 배지의 내부 중복 원인은 이 실행의 원시 로그로 검증하지 못했다. [최신 영상·설정](https://discord.com/channels/1085960591052644463/1574062058117529641/1574091381725470851)

### 2. 일반 Shopify 도구 · 모델이 품목별로 다섯 번 검색

작은 플러그인이 `search_catalog(query, max_price)` 도구를 제공한다. 프롬프트에서 100달러 이하 다섯 품목의 검색 인수를 정하고, Kimi가 첫 응답에서 도구 호출 다섯 개를 병렬로 생성한다. 각 호출이 Shopify에서 상품 하나를 골라 이름·판매처·가격·링크를 돌려준다. 영상에는 첫 호출 615토큰·1,350 TPS, 최종 938토큰·55초, 세션 평균 1,371이 보인다. Blackout Coffee 드리퍼, Lodge 팬, Pack for Camp 머그, Ox & Pine 저널, Stanley 텀블러의 상품 페이지가 이어진다. [원글과 최신 데모](https://discord.com/channels/1085960591052644463/1574062795195023450/1574089622143631411)

### 3. 문맥을 줄인 Shopify 도구 · 둘째 호출을 목록 복사로 단순화

첫 호출에서 Kimi가 품목별 Shopify 검색 5개를 요청한다. 추가 플러그인은 첫 호출의 시스템 지시를 줄이고 도구 호출을 필수로 설정한다. 둘째 호출에서는 도구 정의와 앞선 대화 이력을 빼고, 다섯 상품의 실제 판매자 설명·가격·링크와 목록을 그대로 출력하라는 지시를 보낸다. 출력이 시작되기 전 혼잡 오류에는 2~3초 간격으로 재시도하도록 구현했다. 영상에서 먼저 보이는 1,397이 검색 요청 단계이고, 더 높은 약 1,488이 최종 답변 단계다. 주물팬·드리퍼·저널·텀블러에 Yosemite 머그를 더한 다섯 상품을 보여준다. [원글·영상·설정](https://discord.com/channels/1085960591052644463/1574092434693165086/1574092434693165086)

### 4. 단일 호출 · 플러그인이 상품을 선정하고 Kimi가 출력

`santa-turbo`가 프롬프트의 선물 유형 다섯 개를 읽어 Shopify를 병렬 조회하고 미국 배송·재고·예산·상품명을 기준으로 다섯 상품을 선택한다. 최신 ZIP에는 `santa-fast`도 있다. 이 플러그인은 실제 상품 목록과 간단한 복사 지시만 Kimi에 전달하고, 출력 전 혼잡 오류를 재시도한다. 성공 응답의 서버 시간이나 토큰 수를 다시 쓰는 코드는 검토한 첨부에서 발견되지 않았다. 작성자는 이 방법의 인정 여부를 운영진에게 맡기고 기본형과 두 호출 출품작도 제출했다. [최신 원글](https://discord.com/channels/1085960591052644463/1574070586592993410/1574070586592993410)

1,468 영상은 701토큰·15초, 1,501 영상은 703토큰·51초를 표시한다. 세션 TPS는 올랐지만 사용자가 결과를 받는 시간은 늘었다. 상품은 Kikkerland 드리퍼, Lodge 팬, Parks Apparel 머그, Ox & Pine 저널, Portland Leather 키링이다. 초기 1,382 제출 당시 작성자는 74회 시도·25회 완료·중앙값 907을 공개했고, 더 빨랐던 1,397은 링크 표시 오류로 제출에서 제외했다고 밝혔다. 최신의 180회는 여러 단일 호출 변형의 누적 수치다. ## 우리 실험과 비교할 때

우리 카탈로그 실험에서는 **첫 모델 호출이 도구 1회를 요청하고, Shopify HTTP 요청 1회가 상품 5개를 반환**했다. BrightyBrainiac의 두 호출형 두 가지는 모두 **첫 모델 호출이 품목별 도구 5개를 요청**한다. 1,501 방식은 **모델 호출 전에 플러그인이 품목별로 5번 검색**한다. 따라서 이 기록들로 우리 방식의 성능 상한을 추정할 수 없다. [우리 카탈로그 실험 인계](<../experiments/test/catalog-benchmark/README.md>)

작성자 집계에서 최고값과 중앙값이 가장 높았던 방식도 다르다. 단일 호출형이 최고 1,501을 냈고, 문맥 축소 두 호출형의 완료 중앙값은 1,190이었다. 후자는 완료 6건이고, 네 실험의 시간대·프롬프트·재시도·표본 수가 다르다. 입력 문맥을 줄인 효과나 반복 실행 시 기대 속도를 각각 분리해 입증할 자료는 없다.
