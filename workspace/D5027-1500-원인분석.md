## 생성 속도와 추론량

D5067과 D5099의 첫 호출은 추론 30·31토큰, 총 출력 407·413토큰, 캐시 2,048토큰으로 거의 같았다. 제공사 생성 시간은 299.94ms에서 546.16ms로 82% 늘었다. D5079와 D5103도 첫 추론이 11·10토큰으로 짧았지만 생성 시간은 308.99ms와 393.19ms였다. 실행별 추론 길이로 설명할 수 있는 범위에는 한계가 있다.

D5098·D5099의 최종 표시 답변은 537바이트 단위로 동일했고, 출력 161토큰 중 추론 3토큰, 캐시 읽기 2,048토큰도 같았다. 미캐시 입력은 3,148·3,142토큰인데 제공사 생성 시간은 105.20·197.46ms였다. 두 실행의 개별 요청에는 실행 ID와 실제 조회 메타데이터가 다르다. 과거에 동일 본문을 재전송한 진단에서도 112·175·193ms로 변동했다. [동일 본문 재전송 기록](<TPS 분석 인수인계 - 2026-11-22.md>)

D5103은 같은 답변에 추론이 80토큰 붙었다. 최근 161토큰 최종 세션과 비교해 늘어난 출력 77토큰은 추론 증가분 77토큰과 일치한다. 토큰당 개별 생성 시간·내부 배치·라우팅은 기록되지 않아, 추가 추론에 든 시간과 제공사 처리 속도 변동의 기여도를 따로 산출할 수 없다.

## 429와 완주 기회

중계 HTTP 시도 125건 중 116건이 `queue_exceeded` 429였다. D5100·D5101·D5104·D5105는 첫 요청에서 각각 10회, D5106은 최종 요청에서 17회 429를 받은 뒤 종료됐다. D5102 첫 요청은 429가 없었는데도 중계 왕복 107.42초 중 제공사 생성 시간은 0.661초였다. 공식 TPS의 분모는 제공사의 생성 시간이다. 대기 증가는 마감 전 세션 완료 기회를 줄인다. 429 횟수만으로 성공한 호출의 TPS를 예측하기에는 현재 표본이 부족하다. 중계 원장 (로컬 기록) · [점수 코드](<../experiments/test/tools/ledger.py>)

승인된 30초·60초 교차 비교의 지표는 배정된 주기의 시간당 유효 완료다. 단일 세션 1,500 TPS 초과와 영상 확보 여부는 원래 점수·상품·영상으로 별도 판정한다.

## 직접 바꿔볼 수 있는 조건

기본 설정인 D5108의 첫 요청은 도구가 `web_fetch` 하나이며 `tool_choice="auto"`이고 `parallel_tool_calls`는 미지정이다. 모델은 한 응답 안에서 URL 인자 다섯 개를 이미 작성했다. 첫 생성 출력 398토큰 중 기록된 추론이 31토큰이었다. 나머지 367토큰에는 다섯 호출의 인자와 도구 호출 형식이 포함된다. URL만의 토큰 수는 따로 측정되지 않았다. 첫 요청 본문 (로컬 기록) · [D5108 증빙](<../experiments/test/runs/f039d055-caa3-4ed7-bcc8-e571d4dea5fb/evidence.json>)

가장 작은 새 비교는 첫 호출에만 `tool_choice="required"`를 적용하는 것이다. 저장된 첫 요청 46건에서 원래 시스템 지시와 auto가 37건, 짧은 시스템 지시와 required·병렬 설정을 함께 쓴 요청이 9건이었다. 기존 D5027 조건의 첫 요청 12건과 최종 요청 8건을 메모리에서 변환한 결과 첫 요청의 한 필드만 바뀌었다. 실제 생성 속도에 대한 효과는 아직 측정되지 않았다. 일반 설정에서도 병렬 호출을 수행하므로 명시적 병렬 설정을 함께 바꿀 이유는 적다. 최종 요청은 중계에서 그대로 전달해도 첫 응답 내용이 달라지면 이후 대화 문맥은 달라질 수 있다. [중계 코드](<../experiments/test/tools/request_relay.mjs>) · [첫 호출 기존 실험](<D5027 첫 호출 TPS 실험 결과 - 2026-11-22.md>)

이 조건을 실제 시험하게 되면 기본형과 가까운 시각에 순서를 바꿔가며 비교하고, 모든 전송과 실패를 세어야 한다. 첫 추론 토큰·생성 시간, 캐시 읽기, 최종 161토큰 빈도, 5개 상품 완주율, 전체 세션 평균을 보면 첫 단계 이득이 실제 점수에 남았는지 판단할 수 있다. 실행 간격과 재시도 조건은 양쪽에서 동일하게 둔다.
