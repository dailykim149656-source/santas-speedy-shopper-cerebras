# 첫 호출 도구 선택 방식 교차 비교

기본 D5027 세션의 첫 요청에 `tool_choice="required"` 하나를 적용하면 첫 호출의 추론 시간이 줄고, 다섯 상품을 실시간 조회한 세션의 평균 TPS가 오르는지 확인한다. 단일 유효 세션 1,500 TPS 초과를 기록 목표로 둔다.

| 조건 | 첫 요청 | 도구 조회 후 요청 |
|---|---|---|
| A | 기본 `auto`, 본문 그대로 전달 | 본문 그대로 전달 |
| B | `auto`를 `required`로 변경 | 본문 그대로 전달 |

같은 버전의 중계, 시스템 지시, 도구 정의, 온도 0.2, 낮은 추론, 출력 상한 1,024를 쓴다. 두 조건 모두 정상 완료 뒤 60초 대기하고 429 재시도·실패 후 대기는 기존 정책을 따른다. 별도 30초·60초 비교가 끝난 뒤 시작한다.

## 사용자 요청으로 축소한 실행 수

- **최대 4회**다. 이미 전송한 실행을 포함해 A·B, B·A 순서로 두 쌍만 관측한다.
- D5116(A)은 유효했고 D5117(B)은 첫 요청의 429로 끝났다. 두 번째 B도 유효한 세션을 만들지 못하면 3회에서 비교를 종료한다. 두 번째 B가 유효하면 마지막 A 한 번을 같은 조건에서 진행한다.
- 상품·방식 검증을 양쪽 모두 통과한 쌍에서만 첫·최종·세션 TPS 차이를 계산한다. 429나 검증 실패는 그대로 분모에 남긴다. 한 쌍의 차이로 반복 개선을 확정할 수 없다.
- 별도 재확인 전송은 0회다. 후속 60초·90초 간격 비교는 기본형 A를 사용한다.

각 실행의 첫·최종 TPS와 추론 토큰, 제공사 생성 시간, 캐시 읽기, 상품 검증, 429 횟수, 세션 평균을 비교한다. B 첫 요청은 받은 본문과 전달한 본문의 해시·필드 차이를 남기고, 도구 조회 뒤 요청은 받은 바이트와 전달한 바이트가 같은지 확인한다. [실행별 기록](<D5027-1500-실행기록.md>) · [비교를 제안한 근거](<D5027-1500-원인분석.md>)
