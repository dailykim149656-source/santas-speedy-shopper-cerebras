# Santa’s Speedy Shopper 실측 결과

**갱신 기록(11:46 KST)** · 두 쇼핑몰에서 후보를 네 개씩 조회하고 상품 링크만 반환한 실행의 평균은 **717 tok/s**였다. 재시험 중 전체 시간이 가장 짧았던 실행은 **9.17초**, 평균 **679 tok/s**였다. [속도 개선 비교 실험](#속도-개선-비교-실험)

## 최초 실행

2026년 11월 22일 오전 11시 31분(한국시간), 주최 측 패치를 적용한 OpenClaw 웹 채팅에서 **511 tok/s mean · 535 p90 (server)**를 확인했다. Cerebras의 Kimi K3.1 Pro가 두 판매처의 카탈로그를 조회하고 크리스마스 선물 다섯 개를 골랐다. 다섯 링크를 각각 다시 열어 판매처의 상품명과 상세 페이지 주소를 확인했다. [실측 화면](<쇼핑 바운티 실측 - 2026-11-22.jpg>)

## 실행과 검증

- **입력**에는 두 판매처의 재고 있는 상품 카탈로그 주소만 넣었다. Kimi에게 두 곳을 모두 조회하고 기술에 관심 있는 사람에게 줄 선물 다섯 개를 고른 뒤, 조회 결과에 있는 이름·상품 주소와 추천 이유를 반환하도록 요청했다. [WordPress Mercantile 카탈로그](https://mercantile.wordpress.org/wp-json/wc/store/v1/products?per_page=6&stock_status=instock&_fields=name,permalink) · [RaspberryPi.dk 카탈로그](https://raspberrypi.dk/wp-json/wc/store/v1/products?search=kit&per_page=6&stock_status=instock&_fields=name,permalink)
- **실행**은 패치된 로컬 OpenClaw 게이트웨이의 채팅 명령으로 시작했다. 실제 응답을 생성한 모델은 `cerebras/moonshotai-kimi-k3.1-pro-trial`이다. 같은 세션을 브라우저에서 열어 조회 2건, 추천 5건, 평균과 p90을 확인했다.
- **링크 검증**에서는 반환된 주소 5개가 모두 이번 카탈로그 응답에 포함돼 있었고, 각각 HTTP 200을 반환했다. 판매처가 상품 페이지에 명시한 대표 주소도 다섯 개 모두 Kimi가 반환한 주소와 일치했다.
- **속도**는 Cerebras가 보고한 모델 호출 2건의 출력 토큰 수와 서버 생성 시간으로 검산했다. 도구를 호출한 응답은 290토큰을 594.339ms에 생성해 487.94 tok/s, 최종 답변은 239토큰을 446.936ms에 생성해 534.75 tok/s였다. 두 속도의 산술평균 511.34 tok/s가 화면에서 511로 표시됐다. 쇼핑몰 조회와 네트워크 대기는 이 수치에서 제외된다. [패치의 속도 측정 방식](https://github.com/wkasekende/openclaw-speed-patch/blob/e40e9f7b7ec41ad3fa68181ad297db119e755171/README.md#whats-in-it)

## 속도 개선 비교 실험

공식 웹 채팅에서 확인한 최고 평균은 **717 tok/s**로, 첫 기록 511 tok/s보다 **40.3%** 높았다. 가장 빨리 다섯 링크를 받은 실행은 **9.17초**였다. [최고 기록 화면](<쇼핑 바운티 최고 속도 - 2026-11-22.jpg>)

모든 실행은 같은 Cerebras Kimi 모델과 공식 패치를 사용하고, 이미 실행 중인 게이트웨이에서 매번 새 대화를 만들었다. 각 판매처 주소에 실행마다 다른 조회 값을 붙여 실제 카탈로그를 다시 요청했다. 실행 순서대로 결과를 적었다.

| 요청 방식 | 전송부터 최종 답변 수신까지 | 마지막 성공 시도의 에이전트 처리 시간 | 평균 tok/s | p90 tok/s | 혼잡 응답(HTTP 429) |
|---|---:|---:|---:|---:|---:|
| 기존 요청 1 | 75.45초 | 4.31초 | 559 | 715 | 6회 |
| 링크만 요청 1 | 9.17초 | 8.36초 | 679 | 699 | 0회 |
| 링크만 요청 2 | 111.88초 | 9.04초 | 636 | 739 | 8회 |
| 기존 요청 2 | 79.15초 | 18.13초 | 578 | 912 | 5회 |
| 링크만 요청 · 후보 8개 | 53.32초 | 5.37초 | 717 | 1278 | 6회 |

‘전송부터 최종 답변 수신까지’는 같은 연결에서 요청을 보낸 순간부터 최종 채팅 이벤트를 받은 순간까지 측정했으며, 혼잡 응답에 따른 모든 재시도와 도구 조회가 포함된다. ‘마지막 성공 시도’는 OpenClaw의 마지막 `prompt.submitted`부터 `model.completed`까지다. 최초 511 tok/s 실행의 같은 구간은 9.39초였으며, 최초 실행에서는 전송부터 최종 수신까지를 별도로 측정하지 않았다. 표본이 적고 혼잡도가 달라 요청 문구만의 효과를 분리하기는 어렵다. [공식 채점 기준](https://github.com/wkasekende/openclaw-speed-patch/blob/e40e9f7b7ec41ad3fa68181ad297db119e755171/README.md#entering-the-speed-bounty)

### 최고 점수에 사용한 요청

아래는 최고 점수 실행에 사용한 요청이다. 두 카탈로그 주소에서 실행 식별용 조회 값만 생략했다.

```text
Find 5 real Christmas tech gifts across both shops. Fetch these two live catalogs in parallel. Only output 5 numbered [product name](exact product URL) links from the fetched items.
https://mercantile.wordpress.org/wp-json/wc/store/v1/products?per_page=4&stock_status=instock&_fields=name,permalink
https://raspberrypi.dk/wp-json/wc/store/v1/products?search=kit&per_page=4&stock_status=instock&_fields=name,permalink
```

해당 실행에서 Kimi가 반환한 다섯 상품은 모두 이번 카탈로그 안에 있었다. 각 상세 페이지를 다시 열어 HTTP 200 응답, 대표 주소, 상품명을 대조했다.
