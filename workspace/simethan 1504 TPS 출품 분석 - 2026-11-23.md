## 운영진이 재현할 때 확인할 점

- **제출 당시의 실시간 조회.** 프롬프트 전문을 키로 완성 목록을 프로세스 전역 캐시에 저장한다. 성공한 항목에 만료 시간이나 세션 구분이 없어 같은 프로세스에서 같은 문구로 새 채팅을 열면 Shopify 호출 다섯 개를 모두 건너뛸 수 있다. CSV가 캐시 사용을 명시한 실행은 `a184`다. 제출 세션 `a188`의 캐시 적중·미적중과 거래처 응답은 기록되어 있지 않다. 캐시는 검색을 다시 했는지에 영향을 주며, 서버의 생성 TPS가 조작됐다는 근거는 아니다. [캐시 코드](https://github.com/simethan/santas-speedy-shopper/blob/121842981f3214db7066de4f12540d51195bcc36/patch/turbo1501-transport-block.js#L8-L33) · [캐시 사용이 표시된 실행](https://github.com/simethan/santas-speedy-shopper/blob/121842981f3214db7066de4f12540d51195bcc36/evidence/runs-tail.csv#L3-L8)
- **설치.** README는 컴파일된 전송 파일의 `onPayload` 다음에 코드 조각을 넣으라고 안내한다. OpenClaw와 공식 패치의 정확한 커밋, 전체 변경 파일, 시작 설정은 제공하지 않는다. 조각이 참조하는 `userMsgs`와 `getText`는 그 안에 선언돼 있지 않고, 우리가 대조한 OpenClaw 소스의 해당 파일에서도 찾을 수 없었다. 동일한 빌드를 재현하려면 작성자가 쓴 전송 파일이나 적용 가능한 전체 변경 내역이 필요하다. [설치 안내](https://github.com/simethan/santas-speedy-shopper/blob/121842981f3214db7066de4f12540d51195bcc36/README.md#L19-L24) · [코드 첫 부분](https://github.com/simethan/santas-speedy-shopper/blob/121842981f3214db7066de4f12540d51195bcc36/patch/turbo1501-transport-block.js#L1-L8)
- **점수 검산과 규정.** 공개된 조각에서 측정용 `usage`나 `time_info`를 바꾸는 코드는 보이지 않는다. 제출 호출의 원본 응답 ID와 서버 생성 시간이 없어 영상의 1,504를 독립적으로 재계산할 수 없다. 운영진은 실시간 검색 플러그인을 허용한다고 답했지만, 이 구현은 OpenClaw 전송 파일도 수정한다. 공유된 답변만으로 이 구현의 수상 자격까지 확정할 수 없다. [전송 코드](https://github.com/simethan/santas-speedy-shopper/blob/121842981f3214db7066de4f12540d51195bcc36/patch/turbo1501-transport-block.js) · [운영진 답변](https://discord.com/channels/1085960591052644463/1573839018964029450/1574010455004024843)

## 반복 실험 인계 · 2026-11-23 02:17 KST

실행 담당은 Codex 채팅 **TPS 1500 돌파 계획 수립**이다. 진행 중인 검색어 방식 회차의 원본과 측정값을 저장하고, 아래 조건이 준비된 첫 슬롯부터 새 조건만 직렬 반복한다. 기존 실험 종료 시각인 **11월 23일 02:35 KST**를 유지한다.

1. 테스트 브랜치의 기존 선조회 플러그인과 실행기를 활용한다. 매회 새 OpenClaw 세션에서 제출 프롬프트의 다섯 품목을 Shopify에서 병렬 조회한다. 세션 간 상품 캐시는 끄고, 이번 조회에서 받은 상품명·판매자·가격·직접 링크·판매자 설명(품목당 최대 700자)으로 목록을 만든다.
2. 모델 요청은 짧은 시스템 지시와 목록 복사 지시로 구성한다. 도구 정의 없이 Kimi K3.1 Pro에 한 번 전송한다. 온도 0.1, 추론 `low`, 출력 상한 2,400토큰을 적용한다. OpenClaw 공식 속도 패치로 측정하고, 서버가 반환한 사용량과 생성 시간은 원본 그대로 보존한다.
3. 429 대기 정책과 기존 종료 시각을 적용한다. 실행 ID별로 이번 회차의 조회 증빙 5개, 최종 링크, 측정 호출 수, 출력 토큰, 서버 생성 시간, 공식 세션 평균을 남긴다. 상품이 5개 검증되고 모델 생성이 1회인 세션을 유효로 집계한다. 실패와 429도 전체 시도에 포함한다.
4. 종료 보고에는 전체 시도·429 세션·유효 세션 수, 유효 세션 mean의 평균·중앙값·최고, 1,354.66과 1,673 TPS를 각각 **초과한 횟수**, 최고 회차 증빙 경로를 남긴다. 유효 세션이 없다면 마지막 실패 단계와 보존한 원본 경로를 기록한다. 이 조건의 결과는 실험형 기록으로 분리한다.

기존 구현에서 품목별 선조회는 [speed1500 플러그인](<../experiments/test/tools/speed1500-plugin/index.cjs>), 완성 목록과 실행별 조회 증빙 연결은 [gift8 플러그인](<../experiments/test/tools/gift8-plugin/index.cjs>), 도구 정의 제거는 [요청 중계기](<../experiments/test/tools/request_relay.mjs>)의 `removeToolFields`를 참고한다. 기존 선조회 결과에 판매자 설명을 추가하고, 첫 모델 호출에서 도구 제거가 실제 적용되는지 확인해야 한다.
