# 쇼핑 바운티 평균 1,700 TPS 실험 계획

목표는 한 번의 실제 쇼핑 실행에서 공식 화면과 원본 서버 기록이 모두 평균 **1,700 tok/s 이상**을 보이고, 상품 상세 링크 5개와 60초 이내 영상이 검증되는 것이다. Kimi K3.1 Pro와 주최 측 OpenClaw 패치를 사용한다. 서버가 측정한 각 모델 호출의 생성 속도를 산술평균하며, 네트워크와 판매처 조회 시간은 이 점수에서 제외한다. [주최 측 측정·제출 안내](https://github.com/wkasekende/openclaw-speed-patch/blob/e40e9f7b7ec41ad3fa68181ad297db119e755171/README.md#entering-the-speed-bounty) · [로컬 채점 정의](<../experiments/test/benchmark.json>)

## 1,700까지의 거리

D5012까지 완료된 다섯 카테고리 실행을 집계했다. 각 실행은 첫 번째 모델 호출에서 다섯 판매처 조회 요청을 함께 생성하고, 두 번째 호출에서 다섯 상품 링크를 작성했다. 다섯 조회 모두 같은 판매처의 다른 검색이다.

| 실행 | 온도 | 조회를 지시한 호출 | 답변을 작성한 호출 | 실행 평균 |
|---|---:|---:|---:|---:|
| [D5007](<../experiments/test/runs/ad645a7f-b4ef-4e4d-a688-c0a75a634bfe/evidence.json>) | 0 | 812.0 | 1,463.6 | 1,137.8 |
| [D5009](<../experiments/test/runs/a9530b69-3aed-4ea9-8fd9-9ee1fcb36b51/evidence.json>) | 0.2 | 809.9 | 1,792.6 | 1,301.3 |
| [D5010](<../experiments/test/runs/ec8a1f02-2fc0-4783-a4bb-6601bc3b9108/evidence.json>) | 0.2 | 869.1 | 1,226.1 | 1,047.6 |
| [D5011](<../experiments/test/runs/0f3d9367-99ab-41ae-975f-5df9c7f845ee/evidence.json>) | 0 | 1,208.8 | 1,069.0 | 1,138.9 |
| [D5012](<../experiments/test/runs/8c0618a4-c73e-4e93-9272-42d4697ec02d/evidence.json>) | 0.2 | 992.0 | 758.8 | 875.4 |

두 호출의 속도 합계가 **3,400**이어야 한다. D5009의 최종 1,792.65를 유지하려면 첫 호출의 필요 속도는 약 **1,607.35 TPS**다. 정수 목표는 1,608 TPS로 둔다. 같은 409토큰을 출력한다면 첫 호출의 서버 생성 시간이 505.0ms에서 약 **254.5ms 이하**로 줄어야 한다. 반대로 D5011의 첫 호출 속도를 유지하면 최종 호출에 약 **2,191.25**가 필요하다. 다섯 카테고리에서 관측한 두 단계의 최고치를 서로 조합한 가상 평균은 **1,500.70**이다. 1,500은 중간 점검값으로 삼고, 최종 판정은 한 실행에 실제로 기록된 평균으로 한다.

## 실험 순서

기본 모델·패치, 새 대화, 추론 `low`, 온도 `0.2`, 출력 상한 1,024, 기존 작업공간 지침, 녹화 방법을 고정한다. 각 실행은 새 실행 ID를 사용하고 그 ID로 판매처의 실시간 재고를 읽는다. 이미 진행된 온도 0과 0.2 반복은 기준선 분포에 포함한다. 실행을 시작할 때 최신 장부를 먼저 확인하고, 진행 중인 요청이 끝난 뒤 기존 순차 실행기를 사용한다. [D5009 요청과 설정](<../experiments/test/runs/a9530b69-3aed-4ea9-8fd9-9ee1fcb36b51/plan.json>) · [실행기](<../experiments/test/tools/loop.py>)

| 단계 | 대조 조건 | 변경 조건 | 판별할 내용 |
|---|---|---|---|
| 1. 같은 5개 상품 검색, 조회 인자 명시 | D5009를 재현한다. 5개의 인자 객체에는 각각 `url`만 둔다. | 각 객체에 `extractMode="text"`와 `maxChars=4000`을 함께 지정한다. URL, 순서, 상품 선택, 최종 링크 지시는 동일하게 둔다. | 모델이 실제로 해당 인자를 사용했는지, 5개 도구 응답이 잘리지 않았는지 확인한다. 조회 설정을 요청문에 명시했을 때 첫 호출과 전체 평균이 함께 오르는지 측정한다. |
| 2. 같은 재고 목록, 조회를 묶는 방식 비교 | AI Synthesis의 재고 있는 `eurorack` 검색을 `orderby=id&order=asc`, `_fields=name,permalink`, `per_page=6`으로 한 번 조회한다. | 같은 정렬·필드에서 `per_page=3&offset=0`과 `per_page=3&offset=3`을 한 모델 호출에서 함께 요청한다. | 양쪽 모두 정렬 순서상 앞선 서로 다른 5개를 동일한 번호 링크 형식으로 작성한다. 후보 6개를 얻는 조회 방식이 첫 호출 속도와 최종 호출 속도에 미치는 영향을 비교한다. |
| 3. 가장 좋은 조건 재확인 | 원래 D5009 조건 | 1·2단계에서 선별된 조건 하나 | 서로 가까운 시점의 공식 평균, 첫 호출과 최종 호출, 상품 검증 통과율을 다시 비교한다. |

1단계 D5009의 판매처 응답은 보관된 도구 메시지 기준 약 1,100자씩이었다. 4,000자는 제안한 조회 상한이며 실제 본문의 잘림 여부를 매번 기록한다. 2단계는 두 조회를 함께 요청한 과거 C1에서 조회 지시 호출 1,277.55가 관측된 데서 착안했다. C1 전체는 세 호출에 평균 약 717이었으므로 속도 향상은 새 비교에서 확인해야 한다. 2단계의 두 실행 사이에 재고가 바뀌어 후보가 달라지면 그 차이를 기록하고, 같은 후보를 대상으로 한 속도 비교에서는 분리한다. [C1 증빙](<../experiments/test/runs/694ee975-2931-4496-af62-38fc6650d6a6/evidence.json>) · [WooCommerce 조회·정렬·offset 규격](https://developer.woocommerce.com/docs/apis/store-api/resources-endpoints/products/#list-products)

## 실행 횟수와 판단 기준

- **1·2단계 각각 8회.** 대조를 A, 변경을 B로 놓고 네 쌍을 `AB / BA / BA / AB` 순으로 실행한다. 3단계는 `AB / BA` 두 쌍이다. 새 요청은 최대 **20회**로 제안한다. 각 쌍은 순차 실행하고 기존 요청 간격과 혼잡 시 재시도 간격을 따른다. 한 번이라도 목표 기록이 검증되면 남은 요청은 종료한다.
- **조건 선별.** 유효한 짝이 최소 3쌍이고, 변경 조건이 최소 3쌍에서 공식 평균 우세, 짝별 평균 차이의 중앙값이 **+100 TPS 이상**, 상품 5개 검증 통과 횟수가 대조 조건 이상이면 3단계 후보로 채택한다. +100은 다음 실험에 쓸 시도를 배분하기 위한 제안값이다. 기록 자체는 이 기준과 별도로 보관한다. 두 후보 모두 기준을 못 넘으면 16회에서 종료하고 어떤 호출에서 이득이 사라졌는지 보고한다.
- **기록할 값.** 모든 전송 시도에 조건, 실행 시각, 유효 여부, 각 모델 호출의 출력 토큰·서버 생성 ms·TPS, 전체 평균, 실제 도구 인자와 URL, 상품 5개 검증 및 영상 상태를 남긴다. 여러 모델 턴으로 나뉜 실행도 공식 평균에는 실제 호출 전부를 포함한다. 시간 초과, 429, 링크 오류는 각각의 실패 사유로 집계한다. 이력 조회 오류는 같은 실행 ID로 결과를 복구한다.
- **최종 판정.** 원본 서버 응답 해시 일치, 정밀 평균과 공식 화면 표시 모두 ≥1,700, 실제 상품 상세 페이지 5개 독립 검증, 공식 화면의 점수와 링크를 확인한 60초 이하 영상을 요구한다. 5개 카테고리 조건에서는 요청 순서와 응답 링크를, 2페이지 조건에서는 페이지 순서와 중복 여부를 원본 도구 결과와 대조한다. 합격 1회면 최고 기록을 달성한 것으로 보고하고 반복 성공 횟수는 별도로 표시한다.

실행 시점에 `target-1200`, `focus-categories`, 기존 2,000 목표의 우선순위를 확인한다. 1,700 검증 후 다음 모델 요청을 시작하기 전에 멈추는 조건은 해당 비공개 실험 실행기에 적용한다. 공식 패치와 기존 기록의 채점 기준은 그대로 사용한다. 원본 대조와 영상 길이 검증은 다음 명령으로 할 수 있다. [오프라인 검증기](<../experiments/test/tools/verify_run.py>)

```sh
# speed-bounty-evidence-test 작업 폴더에서 실제 실행 ID를 지정한다.
run_id='<실행 ID>'
raw_dir="$HOME/Library/Application Support/Cerebras Speed Bounty/2026-11-22/raw-test"
python3 -B tools/verify_run.py "$run_id" --raw "$raw_dir/$run_id.json"
ffprobe -v error -show_entries format=duration -of default=nw=1 "runs/$run_id/demo.mp4"
```
