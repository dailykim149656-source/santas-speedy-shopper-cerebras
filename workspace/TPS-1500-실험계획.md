## 어떤 실험에 시간을 쓸 것인가

**같은 다섯 줄을 답한 32건에서 최종 호출이 1,500을 넘긴 두 건은 모두 161토큰이었다.** D5027과 최종 답변 537바이트의 SHA-256이 같고 두 호출이 모두 측정된 상품 유효 실행을 골랐다. 이 중 최종 출력 161토큰인 10건은 최종 호출 중앙값이 **1,219.00**, 범위는 **781.09~1,792.65**, 1,500 이상은 **2건**이었다. 161토큰을 초과한 22건의 최종 호출 중앙값은 **887.86**, 최고는 **1,266.31**이었다. ## 실행 설계

| 조건 | 새 세션이 실제로 하는 일 | 판별하려는 것 |
|---|---|---|
| **A · D5027 대조** | 기존 지시와 시스템 설정으로 Kimi가 filter, mixer, oscillator, echo, cable을 각각 `web_fetch`한다. 재고가 있는 상품의 이름과 상세 링크를 번호순 다섯 줄로 답한다. | 같은 시간대에 기존 방식이 낼 수 있는 점수. |
| **P · 실시간 선조회 후 다섯 줄** | 새 요청을 받은 뒤 네이티브 플러그인이 A와 같은 다섯 카테고리 URL을 조회한다. 모델에는 각 실응답의 순서·이름·상세 URL만 전달한다. 모델이 A와 같은 다섯 줄을 작성한다. | 빠른 최종 답변이 첫 생성으로 옮겨가는지. 한 번에 끝난 비율, 단일 호출의 생성 ms, 전체 세션 평균을 함께 본다. |
| **F · 최종 요청에서만 도구 제거** | 첫 호출은 A와 동일하게 전달한다. 정확한 다섯 도구 응답이 모두 성공한 뒤 최종 요청에서만 `tools`, `tool_choice`, `parallel_tool_calls`를 제거한다. 시스템 문구·조회 도구 응답·출력 지시는 A와 같다. 자료가 부족하면 기존 조회·복구 경로를 사용한다. | 기존 릴레이에서 분리하지 못한 최종 도구 정의의 효과. 첫 호출 속도는 대조 진단값이다. |

P는 기존 gift8의 ID 지정·전체 카드 복사와 구별되는 새 조건이다. 현재 플러그인은 고정 ID 다섯 개를 조회하고 검증기는 카드 JSON 전체 일치를 요구한다. 새 실험에는 카테고리 조회와 다섯 줄 결과의 별도 검증을 추가한다. 매 실행의 실제 카탈로그 응답과 HTTP 상태·시각·해시를 보관하고, 재고 필터·상품명·서로 다른 상세 URL 다섯 개·상세 페이지를 대조한다. 재고 변동은 기록하고 실행마다 그때의 상품을 정답으로 삼는다. P에서 후속 호출이 발생하면 모두 공식 평균에 넣는다. P−A는 전체 쇼핑 방식의 효과로만 해석한다. [기존 네이티브 플러그인](<../experiments/test/tools/gift8-plugin/index.cjs>) · [gift8 검증기](<../experiments/test/tools/gift8_evidence.py>) · [기존 카테고리 조회 검증](<../experiments/test/tools/method_1700.py>)

1. **오프라인 준비.** 고유 캠페인과 새 실행 ID를 사용한다. 기존 영수증·고정 응답으로 P의 이름·순서·링크 검증, F의 첫 요청 통과·최종 필드 변경, 일부 조회 실패와 429 후 재시도를 먼저 점검한다. 각 재시도에서 같은 실행 ID, 시스템 지시, 도구 정책, 선조회 본문 해시가 유지되는지 검사한다. 공식 점수 계산을 그대로 사용하고 이 캠페인에서만 `>=1500`을 판정한다. 기존 일반 검증기는 `>2000`, gift8 검증기는 `>=1700`을 사용한다. [일반 검증기](<../experiments/test/tools/validate.py>) · [실행기](<../experiments/test/tools/loop.py>)
2. **탐색 18회.** A·P·F를 한 번씩 실행하는 묶음을 여섯 번 진행한다. 순서는 `A–F–P / P–F–A / F–P–A / A–P–F / P–A–F / F–A–P`로 고정한다. 각 조건이 첫째·둘째·셋째에 두 번씩 온다. 같은 모델·패치·샘플링·재시도 정책을 쓰고 각 묶음은 같은 시간대에 순차 실행한다. 기존 자동 실험과 겹치지 않는 전용 구간을 사용한다. 각 세션을 요청 전부터 촬영하고, 실패도 18회에 포함한다.
3. **판정과 재확인 최대 4회.** 각 후보를 같은 묶음의 A와 비교한다. 제안 선별선은 6개 묶음에서 유효 쌍 4개 이상, 세션 평균 4승 이상, 짝별 차이 중앙값 +100 TPS 이상, 상품 5/5 성공 수가 A 이상이다. 둘 다 통과하면 차이 중앙값, 동률이면 상품 성공 수로 고른다. 선별 후보는 다른 시간대에 `A–후보 / 후보–A` 두 쌍을 실행한다. 두 쌍 모두 유효하고 후보가 앞서면 반복 개선으로 기록한다. 후보가 없으면 18회에서 종료한다. 이 선별선은 제한된 실험 예산에 대한 의사결정 기준이다.
4. **기록과 재현성.** 어느 조건이든 1,500을 넘긴 유효 세션은 즉시 원본·공식 UI·상품 링크·녹화를 보존한다. 추가 독립 세션이 1,500을 넘겼을 때 목표 재현 횟수도 보고한다. D5027의 원본 평균을 넘고 1,500 미만이어도 자체 기록 경신으로 보존한다. 묶음별 첫 호출·최종 호출·모든 호출의 TPS, 서버 토큰과 ms, 유효/전체 전송, 후속 호출, 실제 입력 해시, 429 횟수와 영상은 별도 열로 기록한다. 설정이 유실된 실행은 원점수와 실패 사유를 남기고 통제된 짝 비교에서 제외한다.

**예산은 탐색 18회와 재확인 최대 4회, 총 22개 새 세션이다.** D5059~D5073의 릴레이 경유 상품 유효 9개 세션 중 7개가 내부 재시도에서 429를 겪었고, 해당 429 응답은 합계 42건이었다. 세션 수와 실제 제공사 요청 수를 별도로 센다. 전송 간 429 한도·대기 정책은 세 조건에 동일하게 적용한다. 여러 차례 시도해서 얻은 단일 최고점과 고정 예산에서 다시 나오는 성능을 함께 보고한다. 실제 릴레이 로그 (로컬 기록) · [재시도 구현](<../experiments/test/tools/request_relay.mjs>) · [공식 측정 범위](https://raw.githubusercontent.com/wkasekende/openclaw-speed-patch/e40e9f7b7ec41ad3fa68181ad297db119e755171/README.md)
